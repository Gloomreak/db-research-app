# Архитектура

## Хранилища и потоки данных

| UI-режим | Путь операции | Место исполнения SQL | Постоянное хранилище |
|---|---|---|---|
| PostgreSQL (сервер) | React → HTTP → FastAPI → psycopg | PostgreSQL | серверная БД |
| SQLite (сервер) | React → HTTP → FastAPI → sqlite3 | SQLite на сервере | файл из `SQLITE_PATH` |
| SQLite WASM (браузер) | React → Repository → Worker → SQLite WASM | Worker браузера | OPFS |

У всех режимов единый интерфейс Repository для CRUD, поиска/фильтров/сортировки, статистики, генерации, исследований и экспорта. Интерфейс не содержит SQL. Server mode сегментирует API URL, чтобы выбор UI однозначно задавал фактическую серверную БД; PostgreSQL и SQLite не делят файл/схему данных. Browser mode не вызывает API для операций данных.

В backend используется общий SQL с позиционными параметрами `?`, преобразуемыми в `%s` для psycopg. Таблицы создаются при первом обращении (идемпотентная инициализация схемы). Подключения открываются на операцию и закрываются контекстным менеджером. В SQLite для каждого соединения включён `PRAGMA foreign_keys=ON`, таймаут блокировок — 15 секунд.

## Решения прототипа

- Аутентификация, совместная работа, синхронизация, резервное копирование и автоматический перенос данных не реализованы.
- Выбран официальный пакет `@sqlite.org/sqlite-wasm`; база обслуживается отдельным module Worker, чтобы выполнить требования OPFS.
- UI хранит только последний выбранный режим в LocalStorage. Данные приложения в LocalStorage не записываются.
- Ошибки OPFS и backend показываются пользователю; откат к другому хранилищу без явного переключения отсутствует.
- API локального прототипа не предназначен для публикации в недоверенной сети.
