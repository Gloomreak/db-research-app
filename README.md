# DataDesk — исследование архитектур хранения

Локальное приложение для управления проектами и задачами и сравнения трёх независимых хранилищ: PostgreSQL на сервере, SQLite-файл на сервере и SQLite WASM с OPFS в браузере. Результаты экспериментов формируются измерениями; приложение не предполагает, что какой-либо режим быстрее остальных.

## Требования

- Node.js 20.19+ или 22.12+ и npm.
- Python 3.11+.
- Для PostgreSQL-режима — Docker Desktop или доступный PostgreSQL 15+.
- Для SQLite WASM — современный браузер с OPFS, `SharedArrayBuffer` и `crossOriginIsolated`; приложение задаёт COOP/COEP заголовки при запуске Vite. Используйте `localhost` или HTTPS.

## Запуск локально

В Windows можно запустить `start-datadesk.bat` двойным щелчком из папки проекта. Скрипт откроет отдельные окна backend и frontend, затем откроет сайт в браузере. Окна терминалов нужно оставить открытыми, пока приложение используется; для остановки нажмите `Ctrl+C` в каждом окне. Если зависимости frontend ещё не установлены, сначала выполните `npm ci`; настройки PostgreSQL должны быть указаны в `.env`.

В корне проекта откройте два терминала.

```powershell
# Терминал 1 — backend
Copy-Item .env.example .env
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

```powershell
# Терминал 2 — frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. В разработке Vite проксирует `/api` к `127.0.0.1:8000`. Сервер SQLite создаётся автоматически в `data\server-research.sqlite3`.

PostgreSQL необязателен для разработки/использования server SQLite. Для запуска локального экземпляра PostgreSQL выполните `docker compose up -d postgres`. Настройте `DATABASE_URL` и `SQLITE_PATH` в скопированном `.env`; шаблон находится в `.env.example`. В коде нет секретов, файлы `.env` исключены из Git.

В production необходимо раздавать собранный `dist` с теми же заголовками COOP/COEP и проксировать `/api` к FastAPI. Серверный API доступен только на текущем origin; внешний доступ и аутентификация в объём прототипа не входят.

## Возможности

- Стартовый обзор с количеством проектов/задач, просроченными задачами, диаграммой статусов, недавними задачами и состоянием активного хранилища.
- CRUD проектов и задач, каскадное удаление проекта, фильтры, поиск, сортировка и агрегированная статистика.
- В исследовательской панели можно очистить проекты и задачи только активного режима; перед удалением показывается подтверждение, схема базы сохраняется.
- Страница проекта со связанными задачами; редактирование задачи открывается в боковой панели.
- PostgreSQL и SQLite работают через FastAPI; каждая БД имеет собственные данные. Для SQLite включены внешние ключи и busy timeout.
- SQLite WASM работает в Worker и хранит базу `datadesk.sqlite3` в OPFS. Данные не помещаются в LocalStorage. Если OPFS/изоляция недоступны, приложение сообщает об ошибке и не переключается на ложное постоянное хранилище.
- Генератор поддерживает 1 000, 10 000 и 100 000 задач и seed. Режим генерации одинаков по последовательности псевдослучайных значений в Python и TypeScript.
- Исследовательские сценарии: JOIN/выборка, LIKE-поиск, GROUP BY, UPDATE/DELETE, запрос до/после исследуемого индекса, COMMIT и ROLLBACK; SQLite WASM дополнительно закрывает/открывает OPFS-БД для проверки сохранения.
- Раздел исследования разделён на сравнение, эксперименты, SQL и транзакции. Выполненные измерения можно повторить с теми же параметрами и экспортировать в CSV/JSON; конфигурацию эксперимента можно сохранить отдельно. История измерений хранится в памяти текущей сессии приложения.

## Метрики и ограничения

Серверные сценарии выполняют прогрев и повторы, возвращают backend-время и среднее/медиану/границы SQL-измерений; UI отдельно считает полную задержку HTTP-команды и размер ответа. В браузерном режиме HTTP-запросов нет. При вставке `sql_ms` и полная задержка операции показываются отдельно. Измерения зависят от оборудования, ОС, версий, браузера, кэша, сети, размера данных и фоновой нагрузки. Это экспериментальный прототип, а не универсальный бенчмарк.
